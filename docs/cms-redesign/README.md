## Что должно получиться

Существующая самостоятельная React CMS должна стать последовательным рабочим
инструментом редактора: ясные списки, удобные формы, управляемые блоки,
предсказуемая публикация, повторное использование файлов и сравнение переводов.
Общий визуальный язык — тёмные рабочие поверхности в фирменной палитре AI DEF,
Inter, строгая типографика, аккуратные таблицы и английский интерфейс.

Меняется существующая CMS `/cms/`, а не Django admin и не публичный сайт.
Сохраняются доменные модели, отдельные сайты AI DEF/ARMS, права, черновики,
история, конфликты, защищённый предпросмотр и публикация.

## Как пользоваться пакетом

Для запуска новой задачи скопировать текст из `TASK.md` в новое сообщение агента
в этом репозитории. Сейчас новая задача не создаётся и реализация не запускается.
Само наличие `TASK.md` на диске не является разрешением на команды или изменение
данных: разрешения из него действуют только после явной отправки пользователем.

Если в процессе будущей реализации код уже изменился, сначала перечитать его и
обновить собственный план. Дата этого пакета не превращает текущие наблюдения в
неизменный контракт. `AGENTS.md` остаётся рабочим договором.

## Решения, которые уже приняты этим заданием

- Перерабатывается существующий React entry `frontend/src/cms/`.
- Тёмная рабочая тема в цветах AI DEF — одна, без переключателя тем.
- Язык интерфейса — английский; язык контента выбирается независимо.
- После входа возвращается запрошенная страница; без deep link открывается
  список продуктов выбранного сайта.
- Отдельный аналитический dashboard не нужен.
- Добавляется минимальная медиатека загруженных CMS-файлов с выбором из формы.
- Переводы редактируются и сравниваются на уровне текущего материала.
- Нет массовой публикации, автоматического перевода, согласования материалов,
  нового page builder, управления папками и физического удаления файлов.
- Все существующие типы контента и служебные операции остаются доступны.

## Что означает «практически идеально»

Не субъективную гарантию, а отсутствие известных провалов в основных сценариях:
редактор понимает текущий сайт, язык, материал, состояние сохранения и последствия
действия; не теряет данные при ошибках; работает мышью, клавиатурой и на узком
экране; отличает черновик от опубликованного сайта; получает конкретное объяснение
каждой блокирующей ошибки. Проверка идёт по `04-acceptance.md`, а не по сходству
одного скриншота с Dribbble.
