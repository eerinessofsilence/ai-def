# Целевая спецификация UI/UX

Статус: задание на реализацию. Все новые возможности ниже — целевые требования,
а не утверждения о текущем приложении. Фактическая база — `01-current-state.md`.

Уточнение пользователя от 24 октября: Untitled UI в тёмных цветах AI DEF,
полностью английский UI, реальные материалы и фотографии обоих сайтов.
Последующий план удобства и YAGNI — `06-usability-roadmap.md`.

## 1. Цель и рабочие принципы

Редактор должен за несколько секунд понять, какой сайт и материал открыт,
какой язык редактируется, что уже сохранено и что увидят посетители после
публикации. Частые операции не требуют чтения технических полей и поиска
кнопок по разным разделам.

Пять оснований: R1 — структура редактора; R2 — визуальная система; R3 —
таблицы; R4 — файлы; R5 — переводы. Изображения лежат в `references/`.

Приоритеты в спорной ситуации:

1. Сохранность введённых данных и действующие серверные права.
2. Ясные последствия действия и точная модель публикации.
3. Полнота существующих типов материалов.
4. Доступность и предсказуемая клавиатура.
5. Визуальная аккуратность и плотность полезной информации.

Необходима одна завершённая рабочая система. Нельзя сделать красивым только
список, оставив старые редакторы, диалоги, загрузчики и ошибки.

## 2. Пользователи и основные сценарии

| Пользователь | Основная задача | Признак хорошего результата |
| --- | --- | --- |
| Редактор | Найти материал, изменить текст/фото, сохранить черновик | Видит подтверждение сохранения, не публикует случайно |
| Редактор с публикацией | Проверить материал, языки и preview, обновить сайт | Понимает объём публикации и получает конкретные ошибки |
| Сотрудник по обращениям | Найти заявку, назначить, добавить внутреннюю заметку | Отделяет действия над заявкой от редактирования контента |
| Управляющий | Переключать сайты, управлять разрешёнными доступами | Не путает сайт, роль и действие над учётной записью |

Ключевые цепочки:

- Список → поиск/фильтр → редактор → сохранение → возврат в тот же список.
- Новый материал → неполный черновик → фото → preview → публикация.
- Опубликованный материал → правки → проверка → обновление на сайте.
- EN → другой язык → сравнение оригинала → ввод → сохранение без изменения EN.
- Файловое поле → медиатека → выбор/загрузка → вставка → alt в материале.
- История → просмотр версии → восстановление в черновик → отдельная публикация.
- Ошибка сети/409 → понятное восстановление работы без молчаливой потери ввода.

## 3. Информационная архитектура

### 3.1. Оболочка

Слева постоянная навигация. Сверху в ней — логотип и выбор сайта с доменом.
Внизу — имя сотрудника, ссылка на публичный сайт и выход. Контент справа.
Выбранный сайт виден и в навигации, и в контексте редактора/подтверждения.

| Раздел | AI DEF | ARMS | Содержание |
| --- | --- | --- | --- |
| Продукты | Да | Да | AI DEF: основной/гражданский каталог; ARMS: свой каталог |
| Статьи | Да | Нет | Статьи, автор и рубрика внутри редактора |
| Страницы | Да | Да | Только предусмотренные макеты своего сайта |
| Медиатека | Да | Да | Загруженные через CMS файлы выбранного сайта |
| Обращения | Да | Да | Обращения выбранного сайта по серверным правилам |
| Клиентский портал | По правам | Нет | Продукты портала и общие модули |
| Настройки | Да | Да | Свой пароль; доступы сайта для manager |

«Переводы» — режим текущего материала, а не отдельная неподдержанная глобальная
система. «История» и «Предпросмотр» — действия материала. Справочники доступны
из соответствующих полей, без добавления пустых разделов в навигацию.

Не добавлять dashboard с графиками, глобальный поиск по разным сущностям,
календарь, уведомления, отдельные команды/организации и настройки дизайна сайта.

### 3.2. Переходы

- Активный раздел заметен текстом/фоном и `aria-current`.
- Переключение сайта проходит через действующую защиту несохранённых правок.
- При смене сайта сбрасываются данные прошлого сайта и связанные запросы.
- URL не теряет site и тип материала; deep link открывается после входа.
- Список сохраняет query string, страницу и корректную позицию возврата.
- Локальный раздел редактора и язык желательно хранить в query string
  (`section`, `lang`) с валидацией допустимых значений. Обновление этих значений
  не должно создавать историю браузера на каждый ввод или выполнять публикацию.
- `from` содержит только проверенные параметры своего списка; нельзя принимать
  произвольный внешний URL как цель возврата.
- Истёкшая сессия не стирает открытую форму автоматическим redirect/unmount.
  Ошибка даёт возможность сохранить текст вручную и заново войти. Редакторский
  контент и заявки не складываются в localStorage ради «восстановления».

## 4. Визуальная система — R2

### 4.1. Направление

Тёмная рабочая область в фирменной navy-палитре AI DEF, светлый текст,
сдержанные голубые акценты и контрастное основное действие. Сохранить логотип
AI DEF и Inter. Компоновка и иерархия ориентируются на Untitled UI; формы,
ссылки, таблицы и rich text согласованы между собой. Один набор иконок Lucide.

Стартовые токены, которые нужно проверить на реальном интерфейсе:

| Токен | Значение | Применение |
| --- | --- | --- |
| Canvas | `#172B4A` | Фон рабочей области |
| Surface | `#1B304E` | Формы, диалоги и кнопки |
| Sidebar | `#10213A` | Навигация |
| Surface muted | `#243B5B` | Вторичные зоны и фон миниатюр |
| Text | `#FFFFFF` | Основной текст |
| Text secondary / muted | `#B4C2D4` | Описание, подписи, вторичные сведения |
| Border | `#344B69` | Декоративные разделители поверхностей |
| Control border | `#7486A0` | Различимая граница поля; минимум 3:1 на базовых поверхностях |
| Accent | `#A9CFFF` | Ссылки и фокус |
| Primary | `#FFFFFF` / `#14243D` | Светлая кнопка, тёмный текст |
| Primary hover | `#DCEAFF` | Наведение на основной action |
| Accent subtle | `#314E73` | Активная навигация и выбранные карточки |
| Danger | `#FF9B95` | Ошибка и опасное действие |
| Success | `#75D6A5` | Подтверждённый результат |
| Warning | `#F6C66B` | Внимание и неопубликованные правки |

Токены — локальные CSS custom properties CMS. Тени слабые, в основном только
у overlay/popover. Радиус контролов 8 px, панелей 10–12 px. Не использовать
градиенты, стекло, декоративные графики, огромные карточки и лишние пустые зоны.
Не менять CSS публичной витрины ради CMS. Portalled Select/Dialog тоже должны
получать тему CMS независимо от цветов публичного магазина.

### 4.2. Размеры и типографика

- Шаг отступов: 4/8/12/16/20/24/32/40/48 px.
- Sidebar на широком desktop: 296 px, на среднем: 240 px; рабочие отступы: 32/24 px.
- Контент списка: до 1440 px; очень широкое окно не растягивает текст бесконечно.
- H1: 28/36 px, 600; H2: 20/28 px, 600; H3: 16/24 px, 600.
- Основной интерфейс: 14/20–22 px; подписи: 13/18–20 px.
- Текстовый редактор: 16/26 px, обычно до 760 px ширины.
- Поле ввода: минимум 42 px; кнопка desktop: 40–44 px.
- Интерактивные цели на touch: минимум 44×44 px.
- Иконки 18–20 px; одиночная иконка имеет название и tooltip.
- Табличная строка обычно 64–76 px; без фото может быть компактнее.
- Текст не делать мельче ради размещения ещё одной колонки.
- Длинные названия переносятся до двух строк; полное название доступно
  при фокусе/в редакторе. Файлы и URL не создают горизонтальный overflow.

Верхняя панель редактора закреплена и остаётся читаемой при scroll. После
перехода к ошибке поле не скрывается под ней: предусмотреть scroll margin.

### 4.3. Единые элементы

Общие правила для Button, IconButton, StatusBadge, Field, ErrorSummary,
EmptyState, Loading/Skeleton, Table, Pagination, Dialog/Drawer и MediaCard.
Выделить общий компонент только при реальном повторении.

| Состояние | Требование |
| --- | --- |
| Default | Контроль узнаваем и имеет ясную подпись |
| Hover | Небольшое изменение фона/границы без сдвига размеров |
| Focus | Контрастное кольцо, заметное на любой поверхности |
| Active / selected | Текст + фон/граница/иконка; не только цвет |
| Disabled | Причина рядом или в доступном пояснении; значение остаётся читаемым |
| Loading | Конкретный текст действия и блокировка повторной отправки |
| Error | Текст рядом с полем и возможность исправить/повторить |
| Read-only | Не выглядит сломанным disabled-полем, содержимое можно скопировать |

Одна основная кнопка на смысловой экран. «Удалить» не является основной
кнопкой обычной формы. Не прятать сохранение, публикацию и язык только за `…`.

## 5. Списки материалов — R3

### 5.1. Структура

1. Заголовок сущности, количество результатов, короткая подпись сайта.
2. Справа — «Добавить продукт» / «Добавить статью» / «Добавить модуль».
3. Для продуктов AI DEF — вкладки «Основной каталог» / «Гражданский каталог».
4. Поиск и действующие фильтры.
5. Таблица или её мобильное представление.
6. Пагинация с итогом результатов.

| Список | Главная колонка | Остальные данные |
| --- | --- | --- |
| Продукты | Фото + название | Категория, состояние, изменён |
| Статьи | Обложка + заголовок | Рубрика, состояние, изменена |
| Портал | Фото + название | Категория, состояние, изменён |
| Модули | Фото/иконка + название | Состояние и изменён, только если корректны для модели |

Не показывать «Категория» с пустым столбцом у сущности без категорий. Не
добавлять автора/языковую полноту в list response только ради имитации R3.
Доступные поля и их семантика важнее буквального числа колонок референса.

### 5.2. Поведение

- Название — настоящая ссылка. Дополнительная зона открытия не мешает
  выделению текста и обычному открытию в новой вкладке.
- Table использует корректные `th`/`td`, либо доступную структуру с эквивалентной
  семантикой; декоративная сетка не объявляется полноценной таблицей без нужды.
- Фото продукта показывать через contain, обложки статьи — через cover.
- Нет фото — нейтральный placeholder; сломан URL — «Изображение недоступно».
- Состояния: «Черновик», «Опубликован», «Есть изменения»; для статьи допустима
  правильная грамматическая форма. Смысл badge один во всей CMS.
- Поиск — Enter или явная кнопка. Без автозапроса на каждый символ и потери фокуса.
- Очистка поиска действительно убирает `q`; фильтр сбрасывает `page`.
- Активные фильтры видны, есть «Сбросить фильтры» при наличии ограничений.
- Запросы отменяются/отсекаются при смене site/kind/filter. Поздний ответ не
  должен показывать материал прошлого сайта.
- При обновлении результатов сохранять оболочку и управление; не мигать
  полноэкранным loader из-за каждого фильтра.
- Пагинация: «1–25 из 83», текущая страница, назад/вперёд. Никакого обещания
  смены размера страницы, пока сервер её не поддерживает.
- Если результат пустой, различать «Материалов ещё нет» и «Ничего не найдено».
- Ошибка списка — объяснение + «Повторить»; её нельзя выдавать за пустой каталог.
- У старых live-записей без `updated_at` — «Нет данных», не выдуманная дата.
- Нет чекбоксов выбора, массовой публикации, удаления и фиктивной сортировки.

### 5.3. Порядок на сайте

Сохранить отдельный режим и серверные правила. Перед входом в него явно
написано: «Изменение порядка применяется на сайте сразу». При активных
фильтрах не сбрасывать их молча: объяснить переход к полному порядку и
сохранить возможность вернуться к прежнему списку.

Перестановка доступна кнопками вверх/вниз. Drag-and-drop не обязателен и
не заменяет клавиатуру. Действия disabled во время запроса. На первой/последней
позиции корректная доступность определяется глобальным порядком, включая
границы страниц. Не скрывать ошибку перестановки. Непубликуемый новый черновик
имеет пояснение, почему его нельзя переместить таким способом.

## 6. Общая структура редактора — R1 + R2

### 6.1. Верхняя панель

Слева: возврат в конкретный список, название, site/тип, состояние материала.
Справа: состояние сохранения, «Сохранить черновик», «Предпросмотр», основное
действие публикации по правам и меню дополнительных действий.

На широком экране сохранить текст подписи сохранения; не заменять его одной
непонятной галочкой. Дополнительные действия: история, копия, снятие с
публикации — только когда они действительно поддерживаются данным материалом.

Сверху формы — язык контента и «Сравнить с EN». Переключение языка не
переключает сайт, публичную локаль или язык интерфейса CMS.

### 6.2. Компоновка

При ширине от 1280 px: основная форма и правая панель свойств 288 px с зазором
24 px. Внутренние вкладки формы располагаются горизонтально. Не делать
постоянно одновременно глобальный sidebar, второй sidebar разделов,
центральную форму и правую панель, если форма становится узкой.

При меньшей ширине свойства доступны во вкладке «Свойства», не теряют данные
и ошибки. На desktop они могут включать категорию, автора, рубрику, даты,
публичный адрес и сводку переводов — только применимые к сущности поля.
Ключевые рабочие поля не дублируются двумя редактируемыми контролами.

Правила вкладок:

- Один выбранный раздел, понятная подпись и количество элементов, где полезно.
- Пустой раздел не скрывает существующую функцию добавления.
- Переход к ошибке выбирает нужную вкладку/язык и раскрывает родительский блок.
- Смена раздела не пересоздаёт материал и не теряет локальный ввод.
- На reload допустимая выбранная вкладка восстанавливается из URL.

### 6.3. Поля

- Постоянный label, краткая помощь при необходимости, видимые единицы измерения.
- Required-поля отмечаются как «Нужно для публикации», если черновик допускает
  неполные данные. Не блокировать черновик требованиями публикации.
- «Общее для всех языков» возле общей группы/поля. Не распространять эту метку
  на реально переводимые поля.
- Ограничение длины брать из schema/модели. Счётчик показывать при практической
  пользе, а не под каждым коротким полем.
- Число — число; пустое значение не превращается неожиданно в ноль. Сохранять
  контракт nullable/default конкретного поля.
- Даты — понятный формат; различать дату материала и время фактической
  публикации. Отображение даты не обещает отложенную публикацию.
- Для выбора связей доступны поиск, текущий вариант, создание/изменение при
  наличии прав. Не загружать в Select тысячи вариантов без необходимости.
- Существующие поля доступны полностью. «Расширенные параметры» допустимы для
  редких настроек, но не для сокрытия функции, которая была в текущей CMS.

### 6.4. Сохранение и публикация

Состояние документа и состояние сетевого сохранения — разные показатели:

| Документ | Значение |
| --- | --- |
| Черновик | Публичной версии нет |
| Опубликован | Подготовленная версия соответствует опубликованной |
| Есть изменения | Публичная версия есть, в черновике другие данные |

| Сохранение | Текст и поведение |
| --- | --- |
| Dirty | «Есть несохранённые изменения»; ручное сохранение доступно |
| Saving | «Сохраняется…»; введённое остаётся в форме |
| Saved | «Черновик сохранён»; только после успешного ответа сервера |
| Upload | «Загружается файл…»; preview/publish ждут завершения |
| Error | «Не удалось сохранить» + причина + повторить; ввод сохраняется |
| Conflict | «Материал изменён другим сотрудником» + безопасные варианты |

Автосохранение сохраняется, текущая задержка 1200 мс достаточна. Не вызывать
новое сохранение на каждое движение мыши или простое открытие вкладки.
Перед preview/publish/выходом использовать существующий flush и upload tracking.
Последующие действия работают с версией, которую вернул сервер.

Текст основной кнопки: «Опубликовать» для нового материала, «Обновить на сайте»
для правок опубликованного. Если публикация невозможна из-за роли, не
показывать разрешающее действие. Рядом можно пояснить: «Вы готовите черновик;
публикация доступна редактору с соответствующим правом».

Подтверждение публикации содержит site/domain, название, действие и прямое
пояснение: публикуется весь подготовленный материал, включая общие поля,
блоки, файлы и переводы, а не только открытый язык. Частичная заполненность
перевода — рекомендация, если сервер не считает её блокирующей.

После успеха обновляются badge, время и подпись кнопки. Нет лишнего redirect
в список. Повторный клик не создаёт параллельную публикацию.

Снятие с публикации — отдельное подтверждение с последствиями для публичной
доступности. Отсутствует у типов без такой операции. Сохранение черновика
никогда не сопровождается похожим на публикацию success-сообщением.

### 6.5. Ошибки и конфликты

Вверху формы — summary с ясными английскими названиями полей и количеством
ошибок. Каждая строка ведёт к конкретному контролу. У поля — тот же смысловой
текст, `aria-invalid`, связанное описание. Технический path может оставаться
внутренним идентификатором, но не является единственной подписью пользователю.

Не скрывать ошибки вкладок и других языков. Индикатор ошибки раздела не
заменяет переход к полю. Ручной ввод не стирается из-за 422/500/502/timeout.

При 409 остановить фоновое повторение конфликтного запроса. Показать
возможности текущего типа: «Сохранить мою работу копией» или «Сохранить мою
версию в историю» для страницы; «Открыть актуальную версию» только с явным
предупреждением о замене текущего ввода. Не реализовывать silent merge или
force overwrite. Не обещать восстановление того, что не было сохранено.

Закрытие вкладки использует beforeunload, внутренние переходы — blocker.
Если сохранить не получилось: «Остаться» и «Уйти без сохранения» с явным
последствием. Простое закрытие предупреждения означает «Остаться».

## 7. Продукты AI DEF и гражданский каталог

Применить общую оболочку к `ContentEditor`. Рекомендуемые разделы:

| Раздел | Что внутри |
| --- | --- |
| Основное | Название, описание, применимые основные поля |
| Изображения | Основные фото, галерея, dropdown image, media карточки на главной |
| Характеристики | Features и sub-features с сохранением иконок |
| Содержание страницы | Технологии, преимущества, info-блоки, CTA |
| Свойства | Категория, slug и остальные применимые параметры |

Схема сервера определяет наличие раздела. У гражданского продукта не
появляется несуществующий `final_cta_block`. Разные коллекции изображений
имеют пояснение назначения: «Каталог», «Галерея страницы», «Карточка на
главной», «Изображение в меню». Их нельзя слить в один массив.

Карточка сложного блока в свёрнутом виде показывает тип, название/первую строку,
небольшой thumbnail при наличии и действия порядка. Не показывать десять
полностью раскрытых пустых форм. Новая карточка раскрывается и получает фокус
на первом содержательном поле. Блок с ошибкой автоматически раскрывается.

Для изображения: просмотр, замена/выбор файла, alt текущего языка, понятное
удаление связи. Отсутствие иконки допустимо там, где модель её не требует.
Файловая и Lucide-иконка сохраняют существующий приоритет; не сбрасывать один
источник при простом переключении представления.

Для OneToOne-блока — «Добавить блок», пока его нет; не предлагать добавить
второй. Порядок меняется только внутри соответствующей коллекции, не между
разными моделями блоков, если backend не имеет общего порядка.

## 8. Продукт ARMS

Те же верхняя панель, язык, сохранение и свойства. Вкладки:
«Основное», «Изображения», «Характеристики», «Варианты», «Свойства».

### 8.1. Основное и обложка

Название/производитель/категория/slug общие. Описание и alt — по языкам.
Обложка продукта относится к каталогу; фотографии вариантов показаны внутри
конкретного варианта. Не подменять одну коллекцию другой.

В основной форме можно видеть небольшой summary обложки и число вариантов,
со ссылкой на нужную вкладку. Это не второй независимый editor тех же данных.
До первого сохранения доступны все части нового продукта.

### 8.2. Варианты

Список карточек или компактный список слева внутри вкладки: название модели,
код, число фотографий, выбранное состояние. Никаких полноэкранных переходов
к ещё одной модели при обычной правке варианта.

У выбранного варианта:

- Код с пояснением уникальности и допустимых значений по текущей валидации.
- Общий `model_name` и отдельная переводимая подпись, если предусмотрена.
- Описание и характеристики выбранного языка.
- Упорядоченные фотографии с alt по языкам.
- Действия перемещения и удаления варианта.

Добавление открывает новый вариант и фокусирует название. При удалении
показывать точное название/код и предупреждение: вариант удаляется из
черновика, публичная версия изменится после публикации. Подтверждение
обязательно для варианта с содержимым. Удаление файла из storage не выполняется.

При публикации выводить правила существующего `ArmsAdapter`, включая нужные
EN-поля, обложку и хотя бы один корректный вариант. Не придумывать запрет
неполного черновика. Общие и вариантные характеристики отображаются раздельно.

## 9. Статьи и блочный редактор — R1

### 9.1. Компоновка

Основная колонка: заголовок, подзаголовок/анонс по существующему контракту,
контентные блоки. Правая панель: автор, рубрика, дата статьи, время чтения,
публичный адрес, обложка/сводка обложек и состояние переводов.

Обложки можно редактировать в отдельной вкладке «Изображения», но из основной
формы к ним ведёт понятный summary. Hero image и hero images сохраняют свои
назначение и порядок. Не удалять одиночную обложку при добавлении коллекции.

### 9.2. Блоки

Использовать существующие типы `text`, `bullets`, `quote`, `image`, `divider`.
Понятное меню «Добавить блок» с названиями и коротким назначением. Без новых
таблиц, колонок, embeds, AI-помощника и свободной вёрстки.

| Тип | Основное редактирование |
| --- | --- |
| Текст | Поддерживаемый rich text, якорь при наличии |
| Список | Структурированные пункты/поддерживаемое поле текущей модели |
| Цитата | Текст и существующие связанные поля |
| Изображение | Выбор файла, alt, остальные предусмотренные подписи |
| Разделитель | Компактное представление и общие действия |

Не удалять прежние `paragraphs/items` при открытии/сохранении и не считать
любой непустой html поводом автоматически очистить legacy-поля.
При изменении типа блока не терять заполненные данные молча: сначала
пояснить последствия или сохранять их в модели, если это допускается контрактом.

Действия блока: свернуть/развернуть, выше/ниже, удалить из черновика.
Дублирование блока не входит в обязательный объём, если его нет сейчас.
Кнопки доступны с клавиатуры. Название действия включает тип/название блока.
После перестановки фокус остаётся на перемещённом блоке.

`Legacy sections` показывать только если они существуют: понятная подпись
«Прежняя структура статьи» и краткое пояснение совместимости. Не скрывать
их данные и не выполнять автоматическую миграцию по факту открытия.

### 9.3. Rich text

Сохранить текущий поддерживаемый HTML и серверную санитизацию. Toolbar:
полужирный, курсив, заголовок, список, цитата, ссылка, обычный текст.
Состояние активного форматирования доступно там, где его можно корректно
определить. Не показывать декоративные инструменты без реализации.

Вставка plain text остаётся предсказуемой; произвольный HTML из clipboard
не становится доверенным. Диалог ссылки сохраняет выделение; после закрытия
фокус возвращается в текст. Не терять курсор из-за autosave и обновления props.
Нельзя менять редакторскую библиотеку ради внешнего сходства с R1.

Справочник автора/рубрики открывается компактным диалогом. Для редактирования
общей записи: предупреждение о немедленном изменении всех материалов и
явная кнопка «Обновить во всех материалах». Это не часть черновика статьи.

## 10. Страницы фиксированных макетов

В списке — название, путь, состояние и изменение; без «Добавить страницу»,
если сервер работает только с существующими макетами.

В редакторе:

- Разделы названы по смыслу публичной страницы и следуют её текущему порядку.
- Внутренние ключи JSON не используются как единственное название.
- У секции короткое объяснение, где она находится на сайте.
- Существующие вложенные массивы и перестановка сохраняются.
- Фиксированная структура не превращается в свободный page builder.
- Hero/видео/документы различаются по назначениям и допустимому upload.
- Ограниченные данные каталога на главной редактируются в своих продуктах;
  в странице остаются только предусмотренные тексты блока.
- Для документов ARMS — название по текущей структуре, PDF, просмотр,
  замена и понятная метка общего файла для языков.

Предпросмотр использует публичные компоненты и текущий PageAdapter.
Пустой перевод не маскируется редактируемой английской копией без пояснения.
Восстановление конфликтной страницы использует stash/историю, не создаёт
вторую публичную страницу с тем же slug.

## 11. Переводы — R5

### 11.1. Обзор

В селекторе/сводке видны язык и вычисляемое состояние:
«Не заполнен», «Частично», «Заполнены проверяемые поля».
Это полнота ввода, не качество перевода и не статус одобрения.
Не использовать «Проверен» или «Актуален», если нет такой модели данных.

Полноту считать из реальных значений выбранного языка до fallback. Основа
для сравнения — непустые переводимые поля EN текущего материала. Общие поля,
ID, ссылки на файлы и пустые необязательные поля EN исключены. Для
структурированных значений использовать понятные смысловые строки; не
объявлять `100%`, проверив одно описание и проигнорировав alt/вложенные блоки.

Если точный полный расчёт для конкретного типа пока не реализован, подписывать
область честно: например, «Описание и alt: 2 из 3». Предпочтение — единый
расчёт покрываемых переводимых полей с указанным знаменателем. Ноль полей —
«Нет полей для перевода», а не ложная полнота. Метрика не меняет правила
серверной публикации.

### 11.2. Сравнение

Кнопка «Сравнить с EN» доступна при выбранном неанглийском языке. В режиме
сравнения EN слева read-only, текущий перевод справа editable. Подписи
«Оригинал · EN» и «Перевод · DE» всегда видны. Общие свойства вынесены отдельно.

Сравнивать текущий смысловой раздел/блок, не создавать рядом вторую копию
всего многостраничного редактора. Для вложенных узлов с ID сопоставлять по
стабильным ID, не по случайному положению в DOM. У массивов характеристик
ARMS без ID показать списки рядом в их текущем порядке; различия числа строк
не должны вызывать перенос значения в чужую строку.

При редактировании высоты колонок могут различаться. Не применять жёсткий
синхронный scroll, который мешает длинному переводу. Структурные действия над
блоками и вариантами общие, не должны выглядеть локальными для одного языка.

### 11.3. Fallback и копирование

- Пустое поле выбранного языка остаётся пустым в редакторе.
- Английский fallback показывается в отдельном read-only пояснении
  «На сайте пока используется английский текст».
- Просмотр, переключение языка и открытие сравнения не записывают EN в перевод.
- Копирование EN — явное действие для конкретного поля/раздела.
- Замена непустого перевода требует подтверждения или существующий текст
  сохраняется, пока пользователь явно не выбрал замену.
- Копируются только переводимые значения; category, slug, media ref, ID,
  порядок, связи, timestamps и публикационный статус не меняются.
- При переходе на другой язык сохраняются правки старого через обычный draft
  lifecycle; задержанный ответ не заменяет ввод нового языка.
- Не выполнять машинный перевод и не добавлять комментарии переводчиков.

На узком экране — «Показать оригинал» над полем/блоком, перевод доступен ниже.
Не уменьшать шрифт, пытаясь поместить две полноразмерные колонки в телефон.

## 12. Медиатека и выбор файлов — R4

### 12.1. Минимальная граница

Новый раздел показывает **файлы, загруженные через CMS выбранного сайта**.
Существующие legacy-файлы связанного материала доступны в самом материале.
Отсутствие legacy-файла в общей медиатеке не означает, что он удалён.
Не сканировать storage целиком и не импортировать все старые файлы без задачи.

Самостоятельная медиатека: поиск по оригинальному имени, фильтр типа,
серверная пагинация, сетка карточек, загрузка. Порядок — новые сверху с
стабильным вторичным ID. Нет папок, переименования, физического удаления,
непроверенного счётчика использования или фонового индексатора.

### 12.2. Карточка файла

- Превью с фиксированным aspect ratio, имя до двух строк, тип.
- Размеры изображения, дата загрузки; размер файла — если доступен без
  неоправданной нагрузки на storage. Неизвестные данные — «Нет данных».
- Изображение, видео и PDF легко различить по подписи/иконке.
- Для видео/PDF нет обещания серверного thumbnail, если генератор отсутствует.
- «Нет миниатюры» и «Не удалось загрузить миниатюру» — разные состояния.
- Сломанная миниатюра не объявляет весь файл удалённым без подтверждения.
- Открытие детали показывает фактические метаданные и просмотр/скачивание
  через безопасный URL текущего файла. Не вставлять внешний произвольный URL.
- Новый upload сразу виден в начале своего каталога без перезагрузки CMS.

### 12.3. Picker внутри формы

Кнопки поля: «Выбрать из медиатеки» и «Загрузить файл». Они ведут в общий
диалог с вкладками «Файлы» / «Загрузка». Для простого сценария выбор файла
с компьютера остаётся быстрым, без обязательного перехода в глобальный раздел.

Контекст picker: текущий site, назначение поля, допустимые типы, single/multiple.
Неподходящие типы исключены или явно недоступны с причиной. В single-picker
ровно одно selected-состояние; в multi-picker видно число и порядок выбора.
Нельзя выбирать asset другого сайта, включая прямую подстановку ID в запрос.

Выбор не меняет документ до кнопки «Использовать файл» / «Добавить N файлов».
Отмена сохраняет прежнее значение поля. После применения фокус возвращается
к полю, показывается новое превью, меняется только черновик. Upload, выполненный
до отмены, остаётся в медиатеке; это прямо поясняется и не маскируется под
откат физической загрузки.

Для старого текущего `{path, storage}` показать его в отдельной зоне «Текущий
файл материала». Не преобразовывать старую ссылку в asset_id без реального
переноса. Новый выбор использует существующий `{asset_id}` и карту media.

### 12.4. Загрузка

Перед выбором указать реальные ограничения поля: JPEG/PNG/WebP до 20 МиБ,
не более 40 мегапикселей для изображения; MP4/WebM до 45 МиБ; PDF до 20 МиБ.
Результат изображения может быть нормализован в WebP сервером. Не обещать
хранение побайтного оригинала и сохранение EXIF.

Drag-and-drop — дополнение к доступной кнопке выбора, не единственный путь.
У каждого файла собственное состояние «Ожидает», «Загружается», «Готово»,
«Ошибка». Если точного upload progress нет, показывать неопределённый индикатор,
а не выдуманный процент. При частичном успехе видны успешные и неуспешные
файлы; повторить можно только неуспешные. Случайно не вставлять уже успешные
файлы второй раз при retry.

Неподдерживаемый формат и размер объясняются до upload, сервер повторяет
проверку. Ошибка сети не очищает очередь без сообщения. Сохранение/preview/
publish не опережают незавершённую вставку файла. Не вводить бесконечные
автоматические retry и не загружать большие видео для карточки в списке.

### 12.5. Alt и удаление связи

Alt зависит от места использования и языка. Один asset может иметь разные
alt в разных материалах. Редактируется рядом с изображением в материале;
picker не переписывает alt других использований.

«Убрать из материала» меняет ссылку в черновике. Физический файл остаётся.
Не предлагать «Удалить навсегда» или автоматическую очистку якобы неиспользуемых
файлов. История и опубликованные материалы могут продолжать ссылаться на них.

## 13. Клиентский портал и модули

Те же список и оболочка редактора; отдельные данные и серверные права.
Разделы: основное, изображения, характеристики, модули, содержание/презентация,
свойства. Для serial/tags и других полей сохранять контракт portal-моделей.

Характеристики показываются по группам плюс «Без группы». Группа и её элементы
видны вместе; ошибочный выбор чужой группы не скрывается клиентским UI.

Вкладка модулей редактирует placements: выбранный общий модуль, группа данного
продукта, порядок. Пояснять отличие «Размещение модуля в продукте» от
«Содержимое общего модуля». Правка общего модуля влияет на все связанные
продукты; ссылка в его редактор имеет такое предупреждение.

Не копировать общие модули автоматически в каждый продукт. Удаление placement
не удаляет сам модуль. У модуля свои фото/характеристики и нет выдуманного
самостоятельного публичного preview.

Preview image и флаг `is_preview` продолжают работать по текущему контракту.
Не подменять их правилом «всегда первая фотография», если пользователь выбрал
другую обложку. Не объявлять публичный portal API защищённым из-за прав CMS.

## 14. Обращения

Список использует общий ритм R3, но лексика и данные относятся к заявкам.
Показывать имя, фрагмент сообщения, продукт/тему, статус и дату. Сохранять
существующие фильтры: поиск, статус, «Назначенные мне», неопределённый источник
для manager. Не добавлять фильтр произвольного сотрудника, если API его нет.

В карточке две области: сообщение/контакты и «Обработка». Поля обработки:
статус, ответственный, внутренняя заметка. Кнопка «Сохранить изменения» явная;
не переносить на заявки автосохранение контентного документа без изменения
контракта и обоснования.

Внутренняя заметка подписана «Видна сотрудникам; клиенту не отправляется».
Копирование контакта имеет короткое подтверждение; неудача clipboard — понятную
альтернативу. Не добавлять отправку писем, чат, CRM pipeline и изменение
исходного сообщения клиента.

Обновление с 409 оставляет заметку в форме и предлагает безопасно перечитать
данные, не перезаписывая другого сотрудника. Сохранение не меняет source/language
и не запускает contact email flow. В макетах и скриншотах — синтетические данные.

## 15. Вход и настройки

Вход оформлен в той же тёмной системе: логотип, рабочий email, пароль,
«Войти», общая ошибка без раскрытия существования аккаунта. Сохранить
autocomplete, серверный throttling, session auth и CSRF. Не добавлять signup,
социальный вход и «забыли пароль» без действующего backend.

Настройки разделены на «Учётная запись» и «Доступ к этому сайту». Смена пароля
не смешивается с ролью сотрудника. Manager видит действующие доступы и ясные
описания трёх ролей. Изменение прав имеет точный site и подтверждённый результат.

«Убрать доступ» объясняет, что аккаунт остаётся и другие сайты не затрагиваются.
Не показывать кнопку удаления аккаунта. Не менять модель безопасности,
не приглашать сотрудника письмом и не отправлять начальный пароль автоматически.
Секретные поля очищаются по закрытию/успеху, не логируются и не хранятся в URL.

## 16. История и предпросмотр

История — drawer/диалог с датой, автором, версией и ясным названием события.
Неизвестное событие отображается нейтрально, не ломает список. Есть «Показать
ранние версии». Сравнение JSON и визуальный diff версий не требуются.

«Посмотреть» открывает конкретную историческую версию. «Восстановить в
черновик» явно указывает: сайт не изменится до публикации. Перед заменой
содержимого сохранить текущую работу по существующему lifecycle и подтвердить
последствие. Нельзя выдавать просмотр версии за восстановление.

Предпросмотр — существующий защищённый рендер публичных компонентов в iframe,
без индексации и публикации. В шапке: название, site, язык, текущий черновик
или номер версии. Есть режимы «Компьютер» / «Телефон».
Ширина телефона — примерно 390 px, но не больше контейнера.

Пока preview загружается, виден индикатор; ошибка API/iframe не оставляет
бесконечный пустой белый прямоугольник. Закрытие возвращает фокус и scroll
в редактор. Preview исторической версии не должен отображать текущую дату/
содержимое так, будто это точно та версия, если API вернул ошибку.

## 17. Адаптивность

| Ширина | Оболочка | Редактор |
| --- | --- | --- |
| От 1280 px | Постоянный sidebar | Основная форма + свойства |
| 851–1279 px | Sidebar сохраняется, отступы сокращаются | Одна рабочая колонка, свойства вкладкой |
| До 850 px | Меню в drawer, короткая верхняя панель | Одна колонка, без вложенных горизонтальных прокруток формы |
| 390 px | Полная работоспособность без общего overflow | Кнопки переносятся осмысленно, поля по ширине |

Не обрезать главную кнопку публикации и не скрывать ошибку сохранения ради
компактности. На телефоне сохранение/preview доступны в верхней панели или
явном меню действий; основной action остаётся видимым. Списки переходят
в карточки либо сохраняют приоритетные колонки; важные данные доступны при
открытии записи. Весь экран не скроллится горизонтально.

Диалоги помещаются в viewport с видимыми заголовком/закрытием и собственным
scroll. Мобильная клавиатура не перекрывает единственную кнопку отправки.
Переводческий split превращается в read-only оригинал над полем.
Grid медиа: 3–4 колонки при достаточной ширине, 2 на планшете, 1–2 на телефоне
при читаемых именах и touch targets.

## 18. Доступность и обратная связь

Цель — WCAG 2.2 AA для изменяемых рабочих экранов. Это критерий проверки,
не предварительное заявление о соответствии.

- Обычный текст: контраст не ниже 4.5:1; крупный — 3:1.
- Значимые границы, фокус и состояния контролов различимы без одного цвета.
- Семантические headings, labels, landmarks, корректные имена кнопок.
- У tooltip есть клавиатурный путь; он не заменяет постоянную важную подпись.
- Tabs используют согласованный keyboard pattern; нельзя объявить role=tab,
  не реализовав соответствующее управление и связь с panel.
- Dialog/drawer: заголовок, описание, focus trap, Escape, возврат фокуса.
- Несохранённые изменения учитываются и при закрытии overlay.
- Изменение порядка доступно кнопками; drag не является обязательным.
- Ошибка объявляется один раз понятным сообщением; autosave не читает каждую
  букву screen reader через избыточные live regions.
- Skeleton скрыт от screen reader; загрузка объявляется коротким status.
- Визуальный порядок соответствует Tab-порядку. Нет фокуса под overlay.
- Reduced motion отключает необязательные перемещения; обычные переходы
  100–180 мс и без анимации размеров большой формы.
- Не использовать эмодзи как единственное обозначение типа, статуса или действия.

## 19. Тексты интерфейса

Короткие конкретные английские формулировки. Термин content допустим в общей
ошибке, но названия экранов/кнопок соответствуют сущности. Технические термины
`Document`, `MediaRef`, `fingerprint`, `schema` не появляются в обычном flow.

| Ситуация | Текст |
| --- | --- |
| Успешный draft save | Saved to CMS |
| Новая публикация | Content published on ai-def.com, с реальным доменом и отдельным обозначением local copy |
| Правки опубликованного | Changes published |
| Недостающий перевод | No translation yet. The website uses the English text. |
| Несохранённый ввод | Unable to save. Your changes remain in the form. |
| Конфликт | This content has already changed. Keep your work before loading the latest version. |
| Удаление связи с файлом | Remove from draft |
| Нет результатов | No results found. Change your search or clear the filters. |
| Пустая медиатека | Files uploaded through this site's CMS will appear here. |

Сообщение успеха отражает подтверждённое серверное действие. Не писать
«Опубликовано», если ответ ещё не пришёл. Ошибки прав не предлагают обходить
доступ через техническую админку.

## 20. Граница завершённой реализации

Обязательны все перечисленные рабочие экраны, состояния и сохранение
контрактов. Необязательные украшения не задерживают завершение. Не входят:
новые бизнес-разделы, массовая публикация, перевод через AI, редакторские
комментарии, расписание публикаций, ревью workflow, SEO-конструктор, глобальный
theme switcher, работа с папками, image cropper, физическая очистка storage,
новая авторизация, аналитика действий редактора и смена редакторского движка.

Критерии приёмки и приоритеты дефектов — `04-acceptance.md`.
