# Текст для запуска отдельной задачи

Текст ниже предназначен для явной отправки пользователем в новую задачу.
Подготовка этого файла сама по себе не запускает реализацию и проверки.

---

Переработай UI/UX существующей CMS AI DEF / ARMS по пакету
`docs/cms-redesign/`. Выполни реализацию полностью, а не только подготовку плана
или замену цветов. Работай в текущем репозитории; сохрани чужие изменения.

Сначала прочитай `AGENTS.md`, затем:

1. `docs/cms-redesign/01-current-state.md`.
2. `docs/cms-redesign/references/README.md`, пять локальных изображений и разборы.
3. `docs/cms-redesign/02-ui-ux-spec.md`.
4. `docs/cms-redesign/03-implementation.md`.
5. `docs/cms-redesign/04-acceptance.md`.
6. `docs/cms-redesign/06-usability-roadmap.md` — актуальные этапы удобства, YAGNI,
   доказательства и оставшаяся внешняя приёмка.

Сверь документы с текущим кодом. Источник истины для уже существующей логики —
код; целевое поведение UI задано спецификацией. Если код изменился, адаптируй
порядок работ без потери требований. Не считай исторический отчёт о проверках
доказательством работоспособности твоих изменений.

Цель: последовательная тёмная CMS в цветах AI DEF, с полностью английским UI,
удобными списками, редакторами продуктов,
статей и страниц, минимальной медиатекой, сравнением переводов, обработкой
обращений, историей и предпросмотром. Сохрани отдельные сайты AI DEF/ARMS,
действующие типы контента и все операции, которые уже доступны сотрудникам.
Детали и границы каждого экрана — в спецификации.

Актуальный ориентир — Untitled UI в тёмной фирменной палитре. Сохрани Inter,
существующие реальные каталоги и фотографии с обоих сайтов. Не заполняй
пользовательскую локалку Demo/Acceptance-продуктами или файлами-заглушками.
Для проверок используй отдельную тестовую БД; одноразовые QA-записи убирай
после сохранения восстановимых доказательств. Проведи ограниченный YAGNI-проход:
убери дублирование и подтверждённо ненужные элементы, сохранив бизнес-логику,
доступность и защиту данных. Не считай число фич доказательством удобства 9/10.

Перерабатывай `frontend/src/cms/` и при необходимости её API в `backend/cms/`.
Используй существующие React, TypeScript, Vite, CSS, Radix Dialog, Lucide,
Select и Collapsible. Не устанавливай новый UI kit, редактор, state manager,
CSS-фреймворк или платный набор. Не подменяй самостоятельную CMS шаблонами
Django admin. Не создавай отдельное демонстрационное приложение.

Сначала коротко укажи файлы и поведение, которые меняешь. Ручные правки —
через `apply_patch`. Реализуй по этапам из `03-implementation.md`, сохраняя
рабочие переходы между этапами. Небольшие переиспользуемые элементы выделяй,
когда они нужны нескольким экранам; не строй универсальный генератор CMS.

Обязательные инварианты: черновик отдельно от публичного контента;
публикация с проверкой версии и прав; ошибки не уничтожают ввод; 409 не
перезаписывает чужую работу; общие поля и связи не размножаются по языкам;
восстановление создаёт черновик; старые media refs и legacy-секции сохраняются;
редактирование обращения не отправляет письмо.

Разрешаю в этой отдельно запускаемой задаче целевые тесты, сборку/typecheck,
локальный браузер и визуальную проверку CMS. Новые тесты допустимы только для
новой существенной логики и контрактов. Изолированную тестовую БД можно
создать штатным тестовым runner и применить миграции только к ней. Если
окружение не даёт надёжно отделить тестовую БД от рабочей, не выполнять
команды, которые могут изменить рабочие данные.

Проверки в браузере с записью допускаются только на отдельно созданных
синтетических данных в изолированном тестовом окружении. Не публиковать и
не удалять существующие материалы, не менять реальные роли и пароли, не
отправлять email. Для визуальной проверки существующих данных допустимо
только чтение. Не запускать проверки на production.

Не разрешаю deployment, публикацию образов, рабочие/production-миграции,
массовую правку контента, сброс БД, физическое удаление файлов и изменение
секретов. Не создавать субагентов и новые чаты без отдельной просьбы.

В финале перечисли реализованные экраны, изменения API, выполненные проверки
с результатами и оставшиеся ограничения. Покажи несколько скриншотов
реализованной CMS из разрешённого локального окружения: список, редактор,
медиатека, сравнение переводов и узкий экран. Не выдавай скриншоты референсов
за собственный результат. Если часть приёмки выполнить невозможно, точно
обозначь её как непроверенную.
