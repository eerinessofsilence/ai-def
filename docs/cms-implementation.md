## Вход и устройство

Локальная CMS: `http://127.0.0.1:5174/cms/`. Старые `/admin/` и `/admin/...`
перенаправляют в неё. Вход — email и пароль существующего сотрудника Django.
Суперпользователь видит оба сайта; остальные получают отдельный доступ к каждому
сайту в настройках CMS. Роли: редактор, редактор с публикацией, управляющий сайтом.
Портал дополнительно требует соответствующего Django permission.

Клиентский интерфейс расположен в `frontend/src/cms/`, HTML entry —
`frontend/cms/index.html`. API, черновики и история — `backend/cms/`.
Существующие модели и публичные сериализаторы используются на сервере;
шаблоны, стили, формы и виджеты Django admin клиентская CMS не использует.
Техническая админка доступна суперпользователям по `/internal-admin/`.

Открывается список продуктов выбранного сайта. Основные разделы: продукты,
статьи AI DEF, страницы, обращения, портал и настройки. Подчинённые блоки,
фотографии и варианты редактируются внутри материала. Авторы и рубрики доступны
из формы статьи. Изменение общего справочника действует сразу, требует права
публикации и отмечено отдельным пояснением в форме.

Материал автоматически сохраняется в отдельный черновик. Публичный сайт меняется
после подтверждения публикации. История позволяет посмотреть предыдущую версию
и восстановить её в черновик; ранние версии загружаются порциями. Конфликтующие
записи не перезаписываются. Для страниц конфликтующую работу можно сохранить
отдельной версией истории. Физические файлы при правках и восстановлении не удаляются.

Редактируемые страницы AI DEF: главная, о компании, технологии, решения,
поддержка. Для ARMS: поддержка, разрешения и сертификаты. Макеты фиксированы;
редактируются тексты и предусмотренные изображения, видео и PDF.
Публичные компоненты получают опубликованные данные через `PageContentProvider`.

## Практические ограничения

В локальной БД есть ссылки на старые изображения, которых нет в локальном media
storage. CMS показывает состояние недоступного изображения и позволяет загрузить
замену; содержимое существующих материалов проверками не подменялось.

Vite предупреждает о размере общего публичного bundle. Редакторы и публичные
компоненты предпросмотра CMS загружаются отдельно по необходимости.

Ограничение попыток входа использует настроенный Django cache. При запуске
нескольких workers нужен общий cache backend для общего счётчика попыток.

Production-развёртывание, проверка production Nginx и миграции production не
выполнялись. Новые маршруты предусмотрены в обоих Nginx-конфигах. В разработке
`CMS_FRONTEND_URL` по умолчанию указывает на порт 5174, в production — на `/cms/`.
Браузерные проверки проводились в Chromium; отдельные Safari/Firefox и проверка
экранным диктором не выполнялись.

## Ограничения исполнения

Пользователь отдельно разрешил локальные миграции CMS, проверки backend,
сборку frontend и браузерные проверки на отдельных тестовых материалах.
Публикация и миграции production в это разрешение не входят.
