# Проверки CMS

## Запуск

Frontend: Node.js 22.13+ (или 24+) и зависимости из lockfile.

```sh
cd frontend
npm ci
npm run test:cms
npm run lint:cms
npm run build
```

Backend: PostgreSQL и Python-зависимости из `backend/requirements.txt`.
У пользователя PostgreSQL должно быть право создания тестовой БД.
Параметры подключения берутся из штатных переменных окружения проекта.

```sh
cd backend
python manage.py test cms --settings=cms.test_settings --noinput
python manage.py makemigrations --check --dry-run --settings=cms.test_settings
```

Настройки `cms.test_settings` принудительно выделяют БД `test_aidef_cms`,
временную папку media, локальную память для почты и cache. Можно задать другое
имя через `CMS_TEST_DB_NAME`; оно должно начинаться с `test_` и отличаться от
имени рабочей БД. Тестовый runner создаёт и удаляет эту БД. Для повторного
локального запуска допустим `--keepdb`. Настройки предназначены только для тестов.

Workflow `.github/workflows/cms.yml` запускает эти проверки на PostgreSQL 16,
Python 3.11 и Node.js 22. Ошибки тестов, линтера, типов, миграций и сборки
завершают job с ошибкой; `continue-on-error` не используется. Публикации образов
и deployment этот workflow не выполняет.

## Что покрыто

- Вход, выход, CSRF, ограничение попыток входа, смена пароля с сохранением сессии.
- Роли, доступ к каждому сайту и порталу, управление участниками без повышения
  существующих прав или перезаписи чужого пароля.
- Реальные агрегаты продуктов, вариантов, статей, страниц, портала и модулей;
  черновик отдельно от публикации, атомарные изменения, история и восстановление.
- Конкурентные правки, изменение сайта вне CMS, сохранение обеих версий,
  сравнения, порядок, переводы, fallback и отметки ручной проверки.
- Медиа: форматы, размеры, фактическое преобразование изображения в WebP,
  поиск, использование файла, чужие assets и недопустимые вложенные записи.
- Frontend: сохранение во время ввода, последовательные CAS-версии,
  ожидание загрузок, конфликты без потери текста, ошибки полей, восстановление
  CSRF, переходы между материалами, различия и покрытие переводов.
- React-компоненты в jsdom: вход и повтор после ошибки, подтверждение удаления,
  доступные диалоги, пагинация, статус сохранения, гайд и очистка его обработчиков,
  очистка вставляемого rich text. Браузер для тестов не запускается.

## Результат 25 октября 2026

95 backend-тестов CMS и 41 frontend-тест. Новые проверки дополнили существующий
набор; они не заменяют сценарии публикации упрощёнными mock-ответами на сервере.
Frontend-тесты изолируют HTTP на уровне fetch; backend-тесты выполняют настоящие
ORM-запросы и сериализаторы на PostgreSQL. Вложенные subTest-сценарии не включены
в число отдельных тестов.

Браузерная/визуальная приёмка, production, реальные письма и нагрузочное
тестирование в этот прогон не входят. Предупреждение Vite о крупном публичном
bundle сохраняется. `npm audit --omit=dev` показывает существующие уязвимости
зависимостей, включая Next.js (он не используется как сервер приложения);
полное обновление зависимостей требует отдельной задачи и регрессионной проверки.
