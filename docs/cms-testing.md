# Проверки CMS

## Запуск

Frontend: Node.js 22.13+ (или 24+) и зависимости из lockfile.

```sh
cd frontend
npm ci
npm audit --audit-level=low
npm run test:cms
npm run lint:cms
npm run build
```

Backend: PostgreSQL и Python-зависимости из `backend/requirements.txt`.
У пользователя PostgreSQL должно быть право создания тестовой БД.
Параметры подключения берутся из штатных переменных окружения проекта.

```sh
cd backend
python manage.py test cms --settings=cms.test_settings --noinput
python manage.py makemigrations --check --dry-run --settings=cms.test_settings
```

Настройки `cms.test_settings` принудительно выделяют БД `test_aidef_cms`,
временную папку media, локальную память для почты и cache. Можно задать другое
имя через `CMS_TEST_DB_NAME`; оно должно начинаться с `test_` и отличаться от
имени рабочей БД. Тестовый runner создаёт и удаляет эту БД. Для повторного
локального запуска допустим `--keepdb`. Настройки предназначены только для тестов.

Workflow `.github/workflows/cms.yml` запускает эти проверки на PostgreSQL 16,
Python 3.11 и Node.js 22. Ошибки тестов, линтера, типов, миграций и сборки
завершают job с ошибкой; `continue-on-error` не используется. Публикации образов
и deployment этот workflow не выполняет.

## Что покрыто

- Вход, выход, CSRF, ограничение попыток входа, смена пароля с сохранением сессии.
- Роли, доступ к каждому сайту и порталу, управление участниками без повышения
  существующих прав или перезаписи чужого пароля.
- Реальные агрегаты продуктов, вариантов, статей, страниц, портала и модулей;
  черновик отдельно от публикации, атомарные изменения, история и восстановление.
- Конкурентные правки, изменение сайта вне CMS, сохранение обеих версий,
  сравнения, порядок, переводы, fallback и отметки ручной проверки.
- Медиа: форматы, размеры, фактическое преобразование изображения в WebP,
  поиск, использование файла, чужие assets и недопустимые вложенные записи.
- Frontend: сохранение во время ввода, последовательные CAS-версии,
  ожидание загрузок, конфликты без потери текста, ошибки полей, восстановление
  CSRF, переходы между материалами, различия и покрытие переводов.
- React-компоненты в jsdom: вход и повтор после ошибки, подтверждение удаления,
  доступные диалоги, пагинация, статус сохранения, гайд и очистка его обработчиков,
  очистка вставляемого rich text. Браузер для тестов не запускается.

## Результат 25 октября 2026

98 backend-тестов CMS и 42 frontend-теста. Новые проверки дополнили существующий
набор; они не заменяют сценарии публикации упрощёнными mock-ответами на сервере.
Frontend-тесты изолируют HTTP на уровне fetch; backend-тесты выполняют настоящие
ORM-запросы и сериализаторы на PostgreSQL. Вложенные subTest-сценарии не включены
в число отдельных тестов.

## Обновление зависимостей 25 октября 2026

`npm audit` по полному дереву, включая devDependencies: **22 → 0** уязвимых
пакетов. Обновлены Axios до 1.20.0, React Router до 7.18.4, Vite до 7.3.7,
baseline-browser-mapping до 2.11.33 и затронутые транзитивные зависимости.
Основные версии стека сохранены; `--force`, overrides и исключения advisory
не использовались. Неиспользуемый `next` удалён вместе с его зависимостями:
приложение использует Vite, импортов Next.js в исходниках нет, `next-themes`
зависит от React/React DOM и сохранён.

Версия Vite выбрана по [security advisory проекта](https://github.com/vitejs/vite/security/advisories/GHSA-9jrq-w75r-8gcw),
Axios — по [выпуску с исправлениями безопасности](https://github.com/axios/axios/releases/tag/v1.20.0).
Lockfile фиксирует исправленные версии. В CMS workflow добавлен обязательный
`npm audit --audit-level=low`, включая инструменты разработки. Отдельный
регрессионный тест проверяет блокировку перехода при ошибке сохранения и
успешный переход после повторного сохранения на обновлённом React Router.

## Обновление Python-зависимостей 25 октября 2026

PyPA `pip-audit==2.10.1` проверил все 12 пакетов отдельного runtime-окружения
Python 3.11, включая транзитивные зависимости: **4 уязвимых пакета → 0**.
База возвращала повторяющиеся advisory ID; количество записей не используется
как число уникальных уязвимостей. Пропусков пакетов и исключений advisory нет.

| Пакет | До | После |
| --- | --- | --- |
| Django | 5.2.7 | 5.2.18 |
| Django REST Framework | 3.15.2 | 3.18.3 |
| Pillow | 12.0.0 | 13.0.0 |
| python-dotenv | 1.2.1 | 1.2.4 |

Django сохранён в ветке 5.2 LTS, Python — 3.11. Переход Pillow на 13 нужен для
устранения найденных проблем декодеров; использованные приложением API сохранены.
Основания выбора: [Django 5.2.18](https://docs.djangoproject.com/en/5.2/releases/5.2.18/),
[DRF security releases](https://www.django-rest-framework.org/community/release-notes/#318x-series),
[Pillow 13](https://pillow.readthedocs.io/en/stable/releasenotes/13.0.0.html).

Проверка выполняется в отдельном окружении; инструмент аудита не добавлен
в runtime-зависимости приложения. Для локального повторения:

```sh
python -m venv /tmp/cms-pip-audit
/tmp/cms-pip-audit/bin/python -m pip install pip-audit==2.10.1
/tmp/cms-pip-audit/bin/pip-audit --requirement backend/requirements.txt
```

В backend job CMS workflow добавлены обязательные аудит `requirements.txt`
с транзитивными зависимостями и `pip check`. При найденных уязвимостях job падает.
Локально дополнительно проверены фактически установленные пакеты через `--path`.
Обновлённые версии установлены в чистое окружение, а не поверх прежних пакетов.

Регрессионные сценарии проверяют JPEG/PNG/WebP → WebP, прозрачность, EXIF-поворот,
отказ на обрезанном изображении, а также вход и отзыв токена DRF. Изолированный
прогон `cms main portal users` проверяет 126 backend-тестов: 98 CMS и 28 общих
сценариев admin, публичных API, миниатюр и email rollback. Файлы тестов временные,
почта перехватывается в памяти, отдельная тестовая БД создаётся и удаляется runner.

Браузерная/визуальная приёмка, production, реальные письма и нагрузочное
тестирование в этот прогон не входят. Предупреждение Vite о крупном публичном
bundle сохраняется. Нулевой аудит означает отсутствие известных advisory на
момент проверки; образы контейнеров, ОС и системные библиотеки не проверялись.
